# Спецификация ЛР № 2: Telegram-агент с MCP-инструментами

Время в примерах — `2026-10-12T09:00:00+03:00`, часовой пояс пользователя
`Europe/Moscow` (контекст базового набора оценки). Агент работает в режимах
`/study` и `/review`. В `/translate` весь текст считается материалом для перевода,
поэтому инструменты там не предлагаются.

## 1. Пользовательские сценарии и наблюдаемый результат

| № | Действие пользователя | Наблюдаемый результат |
| --- | --- | --- |
| U1 | «Какая сейчас погода в Санкт-Петербурге?» | Модель вызывает `get_weather {city: "Санкт-Петербург"}`. Ответ содержит температуру, условия, ветер и источник Open-Meteo. В `/why` записано: «вызов инструмента get_weather», «проверка: пройдена», «выполнение: успешно». |
| U2 | Город с одноимёнными вариантами сопоставимого размера | Бот перечисляет варианты «Название — регион, страна» и просит выбрать. Автоматический выбор не делается, второй запрос к модели не отправляется. |
| U3 | Город не найден | «Не нашёл населённый пункт «…». Проверьте название.» |
| U4 | Погодный API недоступен, таймаут или вернул некорректные данные | «Не удалось получить данные (текущая погода в городе): <причина>. Попробуйте позже.» Модель не получает шанса придумать данные. |
| U5 | «Покажи расписание на завтра.» | `get_schedule {date: "2026-10-13"}`. Ответ перечисляет занятия; для пустого списка бот прямо говорит, что занятий нет. |
| U6 | «Напомни завтра в 18:30 отправить отчёт.», пояс не задан | «Чтобы создать напоминание, сначала задайте часовой пояс…». Подготовленное действие не создаётся. |
| U7 | То же после `/timezone Europe/Moscow` | Сообщение с текстом, датой «13.10.2026 18:30 (Europe/Moscow)», сроком 5 минут и кнопками «Подтвердить» и «Отменить». Запись в `reminders` не создаётся. |
| U8 | «Подтвердить» в течение 5 минут | «Напоминание №N создано: отправить отчёт — 13.10.2026 18:30 (Europe/Moscow).», в `reminders` появляется одна строка. |
| U9 | Повторное или одновременное «Подтвердить» | Второе нажатие отвечает «Напоминание №N уже создано.» или «уже создаётся». Строка в `reminders` остаётся одна. |
| U10 | «Отменить», а затем «Подтвердить» | «Создание напоминания отменено.», затем «Это действие уже отменено.» |
| U11 | «Подтвердить» позже чем через 5 минут | «Подтверждение просрочено (действует 5 минут). Повторите запрос.» |
| U12 | Другой пользователь нажимает чужую кнопку | «Это действие не найдено.» Действие владельца не меняется. |
| U13 | «Напомни вечером про лабораторную.» | Модель вызывает `ask_clarification`, и бот задаёт уточняющий вопрос. MCP не вызывается. |
| U14 | Общий вопрос («разница списка и кортежа») | Обычный ответ без инструмента. В `/why` записано «ответ без инструмента». |
| U15 | `/tools` | Список из MCP-обнаружения: «• имя — назначение (чтение / изменение, нужно подтверждение)». Если сервер недоступен: «Инструменты сейчас недоступны…». |
| U16 | `/timezone Asia/Yekaterinburg` | Зона сохраняется, бот показывает текущее местное время. `Moscow`, `+03:00` и `UTC+3` отклоняются с подсказкой формата. Без аргумента бот показывает сохранённую зону или сообщает, что она не задана. |
| U17 | `/why` | Время (пояс пользователя или расписания), действие, инструмент, резюме аргументов, проверка, выполнение, число вызовов MCP и причина. Без системного промпта, id и чужих данных. Если запросов ещё не было: «Вы ещё не отправляли запросов агенту.» |
| U18 | MCP-сервер не запустился | Бот работает и отвечает без инструментов. Модель получает инструкцию сообщать, что функция временно недоступна. Причина сбоя записывается в журнал. |

## 2. Контракты

Схемы генерируются из `mcp_server/schemas.py`. Во всех `inputSchema` стоит
`additionalProperties: false`. При ошибке инструмент возвращает `isError: true` и
`structuredContent = {"error": {"code", "message"}}`, где `code` принимает значения
`invalid_arguments | unknown_tool | untrusted_caller | timeout | unavailable |
bad_response | conflict`.

### `get_weather` (чтение)

- Вход: `city` — строка 1–100 символов после удаления крайних пробелов,
  в именительном падеже; страну можно указать через запятую.
- Выход: `status ∈ {ok, ambiguous, not_found}`, `query`; при `ok` — `location {name,
  country, admin1, latitude, longitude}` и `current {temperature_c, condition_code (WMO),
  condition, wind_speed, wind_speed_unit, observed_at (ISO 8601 со смещением), timezone}`;
  при `ambiguous` — до 5 вариантов `candidates`; `source = "Open-Meteo"`.
- Неоднозначность: из геокодера берутся точные совпадения названия, а при указанной
  стране — только они. Город однозначен, если он единственный, либо если в нём не
  меньше 100 тыс. жителей и он в 10 раз крупнее следующего одноимённого. Иначе
  статус `ambiguous`.
- Таймаут 10 с, один повтор для 5xx, таймаута и сетевой ошибки.

### `get_schedule` (чтение)

- Вход: `date` — строка по шаблону `^\d{4}-\d{2}-\d{2}$`; дата должна существовать
  (`2026-02-30` отклоняется).
- Выход: `date`, `timezone`, `lessons[] {start, end (ISO 8601 со смещением), title,
  location}`, `source`. Пустой `lessons` означает, что занятий нет.
- Источник — файл из конфигурации `SCHEDULE_FILE`. Путь от модели не принимается.

### `add_reminder` (изменение)

- Вход: `text` — 1–500 символов после удаления крайних пробелов; `remind_at` — ISO 8601
  с явным смещением, только будущее время.
- Доверенный контекст передаётся в `_meta["ru.itmo.assistant/trusted-owner"]`: `owner_chat_id`,
  `action_id`, `timezone`, `arguments_sha256`, `expires_at`, `signature` (HMAC-SHA256).
  Секрет генерируется ботом при запуске и передаётся только дочернему процессу сервера.
- Выход: `reminder_id`, `text`, `remind_at` (нормализовано в пояс пользователя),
  `timezone`, `created` (`false` при повторе того же `action_id`).
- Отказы: нет или неверна подпись, истёк срок, аргументы не совпадают с подписанными,
  сервер запущен без секрета (`untrusted_caller`); лишнее поле, например `owner_chat_id`,
  прошедшее время или пустой текст (`invalid_arguments`).

### Ресурс `schedule://current-week`

- Только чтение, `application/json`: `week_start` (понедельник), `week_end`
  (воскресенье), `timezone`, `days[7] {date, lessons[]}` в формате `get_schedule`.
- Неделя считается по текущей дате в `SCHEDULE_TIMEZONE`. Часы внедряются, поэтому
  границы месяца и года проверяются тестами.

## 3. Состояния подтверждения напоминания

```text
(запрос) ──validate──► pending ──Подтвердить (atomic UPDATE)──► executing ──MCP ok──► done
                         │  │                                       │
                         │  └──Отменить──► cancelled                └──MCP error──► pending
                         └──прошло 5 минут (при нажатии)──► expired
```

- Действие создаётся с `UNIQUE (chat_id, source_update_id)`: повторная доставка того же
  update возвращает уже созданное действие.
- Переход `pending → executing` выполняется одним `UPDATE … WHERE status='pending' AND
  expires_at > now`, поэтому из одновременных нажатий выполняется только одно.
- Ключ идемпотентности на сервере равен `action_id` (`UNIQUE idempotency_key`), так что
  повтор после сбоя не создаёт дубликат.
- Все запросы ограничены `chat_id` нажавшего пользователя. Подпись привязана к точным
  аргументам, поэтому изменённое действие требует нового подтверждения.

## 4. Ограничения агентного цикла

- До двух MCP-вызовов на одно сообщение (`MAX_MCP_CALLS = 2`) и до трёх запросов к
  модели. Попытка третьего вызова останавливает обработку с сообщением «Запрос требует
  слишком многих обращений к инструментам…» и записью `limit` в аудит.
- Решение модели принимается только через нативный tool calling: `tool_choice=auto`,
  `parallel_tool_calls=false`.
- Допустимы только обнаруженные у сервера инструменты и локальный `ask_clarification`.
  Аргументы проверяются по `inputSchema` (jsonschema) до вызова, затем повторно на сервере.
- Для `add_reminder` приложение дополнительно проверяет: часовой пояс задан, локальное
  время однозначно в этом поясе (переходы DST), смещение модели совпадает со смещением
  пояса, время в будущем.
- Результат инструмента проверяется по `outputSchema` клиентом SDK и передаётся модели
  как `{"source", "untrusted_data"}`.

## 5. Критерии приёмки и проверяемые ошибки

| Ошибка или условие | Ожидаемое поведение | Тест |
| --- | --- | --- |
| MCP-сервер не запустился или разорвал соединение | Ответ без инструментов, «Инструменты … недоступны», переподключение | `test_bot_works_without_mcp_server`, `test_tools_down_message_when_model_calls_tool_without_server` |
| Неизвестный инструмент, попытка раскрыть промпт | Отказ без вызова MCP | `test_unknown_tool_from_model_is_rejected`, `test_unknown_tool_is_rejected` |
| Аргументы не прошли схему, лишние поля | Отказ до MCP, причина в `/why` | `test_extra_arguments_are_rejected_before_mcp`, `test_extra_arguments_are_rejected` |
| Таймаут, ошибка или некорректный ответ погодного API | Безопасное сообщение, без выдуманных данных | `test_timeout_after_retry`, `test_unexpected_forecast_structure_is_bad_response`, `test_weather_failure_is_reported_without_invented_data` |
| Результат неожиданной структуры | `bad_result` (outputSchema) | клиент SDK + `ToolCallError("bad_result")` |
| Превышен лимит вызовов | Остановка, аудит `limit` | `test_agent_stops_after_two_mcp_calls` |
| Не подтвердил, отменил, просрочил | Нет записи, понятное сообщение | `test_cancel_then_confirm`, `test_confirmation_expires_after_five_minutes` |
| Повтор update, двойное подтверждение | Одно действие, одно напоминание (PostgreSQL) | `test_repeated_update_creates_one_prepared_action`, `test_concurrent_double_confirmation_creates_one_reminder` |
| Чужое действие | «Это действие не найдено.» | `test_other_user_cannot_confirm_cancel_or_read_action`, `test_user_cannot_touch_other_users_action` |
| Текст, похожий на инструкцию, в данных инструмента | Остаётся данными, правила не меняются | `test_instruction_like_tool_data_stays_data` |
| Прошлое, неоднозначное или несуществующее время, нет пояса | Уточнение, действие не готовится | `test_reminder_arguments_are_validated_before_preparation`, `test_reminder_without_timezone_is_not_prepared` |
| Посторонний MCP-клиент вызывает `add_reminder` | `untrusted_caller` | `test_reminder_without_trusted_context_is_rejected`, `test_server_without_secret_always_refuses_reminders`, `scripts/mcp_check.py` |

Приёмка по базовому набору: действие выбрано правильно не менее чем в 10 случаях из 12,
аргументы корректны не менее чем в 8 из 9 (`scripts/experiment_lab2.py`).
